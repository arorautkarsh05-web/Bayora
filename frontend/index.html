Threat Model, Security Guarantees & Residual Risks (PR-10)

Transparent disclosure of bounded security claims, assumptions, and limitations before interpreting results.

1. Assets Protected

Asset Sensitivity Enforced Protection Mechanism
Unreleased Red-Team Payloads Critical Storage namespace isolation; Blue Team read requests return 403 Forbidden; excluded from general logs via SHA-256 hashing.
Blue-Team Defensive Rules High Storage namespace isolation; Red Team participants blocked from inspecting rules to prevent adaptive evasion.
Model Endpoint & Credentials Critical Internal token gate; direct tenant invocation blocked; orchestrator is the only caller holding the internal secret.
Audit Trail Integrity High SHA-256 canonical JSON hash chain; Ed25519 digital signature over run manifests.
Host Resources Medium Enforced per-test wall-clock timeouts (asyncio supervisor) and request size caps (64KB).

2. Adversaries Considered

  • Curious or Malicious Red-Team Participant: Attempts to inspect blue-team classifier rules or model credentials to tailor exploits. (Blocked by storage namespace & internal model token gates).
  • Curious or Malicious Blue-Team Participant: Attempts to read unreleased attack payloads before evaluation. (Blocked by storage namespace controls).
  • Adversarial Test Input: Malformed or oversized prompt intended to cause path traversal or resource exhaustion. (Blocked by path traversal guards & timeout supervision).
  • Host Log Tamperer: Entity attempting to modify or delete historical test results. (Detected by cryptographic hash-chain verification).

3. Explicit Residual Risks & Limitations Disclosed

• Shared-Host Kernel Limitations: When running in Docker or local process mode, processes share the host kernel. While network separation, filesystem permissions, and resource limits mitigate risks, they do not guarantee safety against hostile kernel exploits.

• Hardware & Timing Side Channels: Cache timing, GPU memory residency, or power measurement side channels are outside the scope of this prototype MVP.

• Unanchored Hash Chain: Hash chaining makes modifications detectable relative to a trusted signature or checkpoint, but does not prevent a privileged host root administrator from rewriting the entire log. Production deployments should anchor checkpoints into external WORM / Object-Lock storage.

• Single Test Suite Disclaimer: A model passing this benchmark is not certified "safe" across arbitrary real-world prompts.
